Method

  • Data is synthetic and seeded, so every run reads the same bytes. The nyc-311 profile has the 41 columns of NYC 311 Service Requests with plausible value spreads.
  • Each file carries a fixed number of bad cells spread over the whole file, each breaking exactly one check: a wrong type, a missing required value, an out-of-range number, a value outside an enum, and a pattern mismatch.
  • A tool is correct when it reports exactly the bad cells it is able to detect. A fast wrong answer is not a result.
  • Every column type in the schema is one Fairspec checks inside polars. Types it parses row by row (durations, geometries, JSON) would be slower, and are not measured here.
  • Every tool runs as its own process from a warm file cache. Time is wall clock. Memory is the peak anonymous memory of the tool's processes, sampled every 50 ms: memory-mapped pages of the input file are excluded, since the kernel can drop them at any time. Each tool is capped at the memory the report header names; the machine was shared with other work.
  • Reproduce: pnpm -C benchmark setup:rivals, then pnpm -C benchmark measure --case nyc-311 and pnpm -C benchmark show:report.
